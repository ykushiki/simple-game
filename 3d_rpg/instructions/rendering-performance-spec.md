# 3D描画・レンダリング・パフォーマンス設計方針

## 1. メモリ管理とリソース破棄（WebGL Memory Leak 防止）
- ジオメトリ（BufferGeometry）/ マテリアル（Material）/ テクスチャ（Texture）は可能な限り共有・再利用する。
- ダンジョン再構築、モンスター削除、パーティクル再生成時には、不要になった非共有リソースへ dispose() を実行する。
- 共有リソース（壁・床・小物・モンスター共通形状/材質）は共有フラグ管理し、誤破棄を防ぐ。

## 2. ライティング & パフォーマンス最適化
- リアルタイムシャドウを使うライトは必要最小限（プレイヤー松明）に限定する。
- castShadow / receiveShadow はコストの高い組み合わせを避け、静的小物は必要最低限に留める。
- requestAnimationFrame 内で new THREE.Vector3() / new THREE.Mesh() などを生成しない。
- 毎フレーム更新は既存バッファ（Float32Array, Vector3 など）を再利用する。

## 3. プロシージャルテクスチャ生成
- 外部画像依存を減らすため、石壁・石床・木目は CanvasTexture で動的生成する。
- 凹凸感は bumpMap / roughnessMap を併用して PBR 近似表現とする。
- 生成したテクスチャは使い回し、フロア遷移ごとに無駄な再生成をしない。

## 4. 品質チェック観点
- フロア切り替えや再挑戦を繰り返しても描画が重くなり続けない。
- モンスター撃破や扉開閉後に、不要オブジェクトが残留しない。
- 見た目を維持しつつ、GPU/CPU 負荷が過度に増えない。
